# Minimal Microsoft Foundry

`main.bicep` targets an **existing resource group**: AIServices S0 account, optional lightweight project (`createProject=true`), two PAYG deployments, and optional account-scoped Cognitive Services OpenAI User RBAC. No Search, database, storage, telemetry, fine-tuning job, capability host, or agent compute.
Student serves extraction/reconciliation and is **required**, with explicit model name/version/SKU/capacity; there is no implicit student model. A documented smaller example is `gpt-5-mini`/`2025-08-07` (currently GA, not a regional availability or quality guarantee). Embeddings default to `text-embedding-3-small`/`1`, capacity 1. Capacity units vary by model/SKU, are not a spending cap, and GlobalStandard may process outside the resource region.
Teacher is **OFF** (`teacher=null`); to enable, supply `{deploymentName, modelName, modelVersion, sku, capacity}` using independently verified values. All models use format `OpenAI`; deployment names must be distinct. Student/embedding use the same object shape. Only PAYG Standard/GlobalStandard/DataZoneStandard are accepted; no reserved throughput. Versions are pinned with `NoAutoUpgrade`; monitor retirement and re-evaluate replacements.
Authentication uses Entra ID only (`disableLocalAuth=true`); public HTTPS is enabled, not private networking. Optional `operatorPrincipalId` is the identity's object ID; choose `operatorPrincipalType` User/Group/ServicePrincipal (also managed identities). RBAC creation needs role-assignment write permission; otherwise arrange inference access separately. Allow propagation time.
From the repository root, offline compilation/lint: `az bicep build --file infra\main.bicep --stdout > $null`; `az bicep lint --file infra\main.bicep`. Focused regression tests: `uv run pytest -q tests\unit\test_infra.py` (explicitly skips if Azure CLI/Bicep is unavailable). No login or cloud deployment is needed; tests disable version checks/telemetry and remote module restore.
Before any deployment, explicitly choose `$subscription`, `$rg` (existing), `$region`, and a locally reviewed ARM parameters file `$parameters` (see below). Confirm context with `az account show --subscription $subscription`; inspect catalog via `az cognitiveservices model list --subscription $subscription --location $region -o json` and quota via `az cognitiveservices usage list --subscription $subscription --location $region -o json`. Verify exact model/version/SKU, lifecycle/access restrictions, capacity minimum/step, available quota, residency, and [prices](https://azure.microsoft.com/pricing/details/cognitive-services/openai-service/); quota is not a guarantee of available deployment capacity.
Review only: `az deployment group what-if --subscription $subscription --resource-group $rg --template-file infra\main.bicep --parameters "@$parameters" location=$region --mode Incremental`. What-if needs Azure permissions and does not guarantee model deployability.
**Only after review/authorization**, provision with `az deployment group create --subscription $subscription --resource-group $rg --name ekb-models --template-file infra\main.bicep --parameters "@$parameters" location=$region --mode Incremental`; this can incur charges. This change has **not** been live deployed or tested against subscription quota/model access; no inference calls were made.
The ARM parameters JSON uses schema `https://schema.management.azure.com/schemas/2019-04-01/deploymentParameters.json#`, `contentVersion: "1.0.0.0"`, and `parameters: {"student":{"value":{"deploymentName":"ekb-student","modelName":"<verified model>","modelVersion":"<verified version>","sku":"<verified PAYG SKU>","capacity":1}}}`; add `embedding`, optional `teacher`, `accountName`, `operatorPrincipalId`, `operatorPrincipalType`, or `createProject` the same way. Placeholder values are not deployable; adjust capacity from live quota results. For the GPT-5-mini reasoning example, explicitly set application YAML `model_temperature: null` (omit temperature) and `model_max_token_parameter: max_completion_tokens`; these correspond to `EKB_MODEL_TEMPERATURE` and `EKB_MODEL_MAX_TOKEN_PARAMETER`. Do not assume a literal environment string `"null"` parses as a nullable float. Budget `model_max_output_tokens` for reasoning plus visible output; validate actual model quality/cost. These runtime options are not infrastructure parameters or automatic outputs.
Read outputs without keys: `az deployment group show --subscription $subscription --resource-group $rg --name ekb-models --query properties.outputs -o json`. `ekbEnvironment` matches existing EKB settings, using deployment names and the OpenAI `/openai/v1/` endpoint (not a project endpoint); apply those values to your process environment, keep `EKB_MODEL_API_KEY` unset, and authenticate DefaultAzureCredential (local `az login` or the assigned workload identity). `teacherDeploymentName` is separate and never enables teacher calls automatically; grounded distillation/evaluation is application-controlled, not a fine-tuning deployment.
Incremental redeployment with `teacher=null` does **not** delete a previously deployed teacher; explicitly retire unwanted deployments after checking callers. Changing embedding models requires reindexing. Keep application/database deployment separate; see [existing deployment contracts](../deploy/README.md).
